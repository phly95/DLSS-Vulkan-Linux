# SR stage weight blobs: the byte map

Generated by `build/venv/bin/python -I tools/sr/sr_layout.py --markdown` from NeuralHub's own
packer (`tools/sr/sr_pack.py`, `pack_layer` = FUN_180111850). The tool runs the packer on
zero-filled slots and records every write, so offsets, sizes, shapes and encodings are the
packer's, not a reading of the ISA or of probe results. Regenerate it rather than editing it.

**Check a hypothesis against this map before crafting a probe.** Three conclusions of the
2026-10-26 campaign (the "unread" stage0 tail, raw-order f16 reads, the attention topology) were
contradicted by it; see `docs/notes/k_sr_stage.md`, "Review R1".

Encodings (Blob in `sr_pack.py`, LAYOUT = 1 at both call sites):

- **frag fp8**: element (r, c) of a rows x cols E4M3 matrix is at byte
  `frag_offsets(rows, cols)[r, c]` (= the shaders' `frag_off(r, c, cols)`). With LAYOUT = 1 the
  `op` argument ("A"/"B") is ignored.
- **f16 PERMUTED**: an n-half vector with n % 32 == 0. Blob position i holds logical element
  `P[i]` within each group of 32 (`P = 0,1,16,17,2,3,18,19,...`, the shaders' `P`), so logical
  channel c is at blob index `invP[c]`. Reading `read_f16(base + 2*c)` for channel c is wrong.
- **f16 plain** / **f16 block plain**: stored as is.

The note column's semantics (gain order, V = K, output projection, second output) are measured
against the oracle (Review R1), not packer facts.
