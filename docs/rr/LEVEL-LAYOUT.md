from NeuralHub's own packer (`tools/rr/rr_pack.py`: `build_w` = FUN_18012ba70 and `pack` =

`--packed` also compares every unit's size and 21 item offsets with `build/rr/packed/params.json`,
the packer's output on the real tensors; the packer itself asserts no blob size (only the tensor
counts and the fragment bijection), so that comparison is the size check.

**Check a hypothesis against this map before crafting a probe.** The map is what the packer writes.
Where a shader reads a blob, the permutation column says which inverse it must apply.

Encodings (`rr_pack.py`; every rule below is checked numerically by `rr_layout.py`, `check_rules()`):

- **fp8 fragment** (`frag_rr`, FUN_180133070). Rows are padded with zero rows to a multiple of 16. The
  element (r, c) of the padded matrix is at byte `FRAG(r, c) = 16 (u & 15) + 256 bit2(c) + 8 bit3(c) +
  4 bit1(c) + 2 bit4(c) + bit0(c) + 512 (c >> 5) + 16 cols (u >> 4)`, where `u = P^-1(r)` when
  `permute_rows` is set and `u = r` otherwise. Only the head (`m108`) is written without the row
  permutation. The column count must be a multiple of 32 (the packer refuses 16 and 48), and with
  `permute_rows` the row count must be a multiple of 32. This is not SR's fragment order: for a 64 x 32
  matrix without the row permutation the two agree on 128 of 2048 positions.
- **f16 P** (`f16_rr`, FUN_1801336e0). A vector of n halfs with n % 32 == 0 is stored with blob
  position i holding logical element `P(i)` of its group of 32, `P(i) = (i & 1) | ((i & 2) << 3) |
  ((i & 0x1c) >> 1) | (i & 0xe0)` (SR's P). Otherwise it is stored plain. The fragment row permutation
  `u` is the inverse of this P.
- **perm_cols / perm_rows / perm_vec(C)** (FUN_18012e4b0, FUN_18012e5e0, FUN_18012e6f0), applied in
  `build_w` to the 4C-wide input of a down- or up-projection, with the C of the layer that input comes
  from: blob position j holds logical element `j // C + 4 (j % C)`, so logical element L is stored at
  `pos(L) = (L % 4) * C + L // 4`.
- **Composition.** The permutation of `build_w` is applied first, then the writer's own. So: `(R, L)` of
  a `perm_cols` matrix (then `frag_rr`) is at `FRAG(R, pos(L))`; `(R, c)` of a `perm_rows` matrix is at
  `FRAG(pos(R), c)`; a `perm_vec` vector (then `f16_rr`) has logical L at blob index `P^-1(pos(L))`.
- **raw**: the symmetric gram matrices (`sym_scaled`, FUN_18012dfc0: plain f16 64 x 64, row-major, not
  fragments), the 16-half head bias block (plain; the 3 or 4 values, then zeros) and the 4096-byte
  dither table (blob0 only, `meta[20]`).
- **Items**: 16-byte aligned (`B.align()`), offsets in `meta[0..20]` (-1 = absent). `meta[0]` is the
  first fp8 group; the groups follow at `meta[0] + i * 64 C`; the gram matrices at `meta[1] + j * 8192`.

Semantics are packer labels unless measured. The labels in the write column are the packer's own
`W+0x..` names (the offsets of its W struct, as quoted in `rr_pack.py`) and the packer's descriptions
(HOST-RE for the encoder and decoder roles). Every other region is "semantics not yet decoded". Nothing
here is measured on the GPU: the encoding rules are checked against the packer's own functions, and
the sizes and offsets against its output. No weight value is in this file.

Scalars are not in any blob: `s1d0` (f16 at +0x1e0), `s1d2` / `s1d4` (u16 at +0x220 / +0x222, +4 for
the `_1` units), `s1d6` (u16 at +0x228, decoder units), and unit 15's `dec0_scalars`; they are in
`params.json` (HOST-RE: the engine keeps the decoder scalars in E).
